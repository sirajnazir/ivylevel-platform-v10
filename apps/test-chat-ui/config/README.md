# Configuration System

This directory contains all configuration files for the universal KB retrieval system.

## Policy Versioning

The `policy.json` file is a **symlink** to the active policy version (e.g., `policy.v1.json`).

### Why Versioning?

- **History**: Every policy change is tracked with a version number
- **Rollback**: Easy to revert to a previous policy version
- **A/B Testing**: Can run experiments with different policy versions
- **Git Diff**: Clear diffs show exactly what changed between versions

### Creating a New Policy Version

```bash
# 1. Copy the current version to a new version
cp config/policy.v1.json config/policy.v2.json

# 2. Edit the new version
# ... make your changes to policy.v2.json ...

# 3. Update the symlink to point to the new version
ln -sf policy.v2.json config/policy.json

# 4. Commit both files
git add config/policy.v2.json config/policy.json
git commit -m "feat: policy v2 - added XYZ priors"
```

### Rolling Back

```bash
# Point symlink back to v1
ln -sf policy.v1.json config/policy.json
git add config/policy.json
git commit -m "rollback: revert to policy v1"
```

## Configuration Files

### `policy.json` (versioned)

Controls retrieval behavior:
- **Confidence thresholds**: Minimum score for top-1 hit
- **Assessment gate**: Whether to require assessment chips in top-N
- **Priors**: Base namespace priors + tag-specific priors
- **Rerank weights**: Semantic, lexical, and type prior weights

### `intent_lexicon.yaml`

Maps query patterns to tags and type preferences:
- **Regex patterns**: Match user queries to intents
- **Tags**: Add semantic tags for policy-driven boosting
- **Type preferences**: Hint at preferred chip types

### `scaffolds/*.yaml`

Handcrafted templates for high-value query patterns:
- **Priority**: High priority (90+) for premium experiences
- **Select rules**: Smart chip selection with prefix/type matching
- **Template**: Handlebars template with rich formatting
- **Outputs**: Which chips to cite as evidence

### `scaffolds/_auto/*.yaml`

Auto-generated scaffolds for all chip types:
- **Priority**: Medium priority (50) - fallback to handcrafted
- **Generated by**: `tools/scaffold_miner.ts`
- **Coverage**: 33 scaffolds covering all chip types × namespaces

## Regenerating Auto-Scaffolds

```bash
# Run the scaffold miner
tsx tools/scaffold_miner.ts

# This will regenerate all files in scaffolds/_auto/
# based on the current Pinecone index contents
```
