## Key Technical Decisions

### 1. OpenAI Function Calling vs Custom LLM Routing
**Decision:** Use OpenAI function calling for tool execution
**Rationale:**
- Native support for structured tool definitions
- Automatic parameter validation
- Built-in retry logic
- Lower latency than custom LLM routing
- Better error messages

**Trade-offs:**
- Vendor lock-in to OpenAI
- Requires OpenAI API key
- Limited to OpenAI-supported models

### 2. Intent-Based Routing vs LLM Routing
**Decision:** Pattern matching for agent routing (not LLM)
**Rationale:**
- Fast (< 100ms)
- Deterministic
- No API cost
- Easy to debug
- 80% accuracy sufficient (fallback to GamePlan)

**Trade-offs:**
- Manual pattern maintenance
- Less flexible than LLM routing
- Requires periodic pattern updates

### 3. Session Management: In-Memory vs Database
**Decision:** In-memory session storage
**Rationale:**
- Fast access (< 10ms)
- Simple implementation
- No additional database load
- Sufficient for current scale

**Trade-offs:**
- Lost on server restart
- Not suitable for distributed deployment
- No long-term conversation history

### 4. Knowledge Moat: Separate Tables vs KB Vectors
**Decision:** Structured SQL tables (not vectors)
**Rationale:**
- Deterministic queries
- Fast lookups with indexes
- Easy to validate and audit
- No embedding costs
- Precise filtering (e.g., college=Stanford, year=2023)

**Trade-offs:**
- Less flexible than semantic search
- Requires schema design upfront
- Harder to add unstructured data

## Lessons Learned

### What Went Well
1. **Incremental Approach:** Adding one component at a time reduced risk
2. **Comprehensive Testing:** Golden tests caught issues early
3. **Documentation:** Writing docs as we built helped clarify design
4. **Code Reuse:** Wrapping v14 resolvers as tools was fast and robust
5. **Type Safety:** TypeScript caught many bugs before runtime

### What Could Be Improved
1. **Test Coverage:** Need more edge case tests
2. **Performance:** Parallel tool execution would significantly speed up responses
3. **Error Messages:** Could be more user-friendly
4. **Documentation:** Need more examples in API docs
5. **Monitoring:** Need better observability (metrics, traces)

### Unexpected Challenges
1. **OpenAI Agents SDK:** Not publicly available, had to build custom framework
2. **Port Configuration:** AGENT_PORT env variable not consistently read
3. **Apostrophe Syntax:** esbuild/tsx parsing issues with apostrophes in strings
4. **Session Persistence:** In-memory sessions lost on restart (acceptable for now)
5. **Response Times:** OpenAI API latency higher than expected (5-8s)
