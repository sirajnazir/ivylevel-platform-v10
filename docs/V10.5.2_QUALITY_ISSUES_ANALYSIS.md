## 🎯 ROOT CAUSE ANALYSIS

### Root Cause 1: **Context-Blind Humanizer**

**Location:** `services/jenny-api/src/lib/humanizer.ts:200-203`

**Current Logic:**
```typescript
const phrases = await loadJennyPhrases(studentId);
const seed = `${studentId || "anon"}|${intent || route}`;
const opener = seedPick(phrases.warmth, seed) || "I'm with you.";
```

**Problem:**
- Humanizer loads EQ phrases from iMessage/session history
- These phrases are from **emotional support conversations** (Cat-3 context)
- Phrases are randomly selected using seed-based picking
- **No filtering by query type or semantic relevance**

**Why It's Broken:**
- "You have momentum on both projects" came from an EQ conversation about project management
- "4/2? That's more than 2" came from a conversation about schedule conflicts
- These phrases are **semantically appropriate for their ORIGINAL context** but **completely wrong for factual queries**

**Impact Scope:**
- ALL Cat-1 queries (awards, IvyScore, college, GPA, etc.)
- ALL queries where EQ phrase database has emotional/coaching content

---

### Root Cause 2: **SQL Deduplication Missing**

**Location:** `services/jenny-api/src/resolvers/enums.ts` (awards resolver)

**Current Logic:**
Awards are fetched from multiple source tables:
- `kb_items` where `source_id` IN ('SRC-IMSG-2023-2025', 'SRC-INT-NCWIT-NAT', 'SRC-INT-NCWIT-REG', ...)
- No `DISTINCT` on award name + date combination
- Each award appears multiple times with slightly different formatting

**Example Duplication:**
```sql
-- Both rows returned:
award: NCWIT Aspirations in Computing - National Awardee | src: SRC-IMSG-2023-2025
award: NCWIT Aspirations in Computing — National Awardee | src: SRC-INT-NCWIT-NAT
       ^^ hyphen vs em-dash, but SAME award
```

**Why It's Broken:**
- Data ingestion creates multiple `source_id` entries for same award
- One from iMessage scraping (SRC-IMSG-*)
- One from intent-based ingestion (SRC-INT-*)
- Resolver queries ALL sources without deduplication logic

**Impact Scope:**
- Awards: 12 displayed instead of 6
- Activities: 20 displayed with SRC-CAPP + SRC-COMMONAPP overlap
- ANY enumeration that ingests from multiple sources

### Root Cause 3: **Intent Classification Too Coarse**

**Location:** `services/jenny-api/src/orchestrator/intent-enum.ts:267-332`

**Current Logic:**
```typescript
// PROBLEM: "Am I ready for top colleges?" matches COLLEGE_SYNS
// Routes to college.list instead of ivyscore.latest

if (containsAny(msg, COLLEGE_SYNS)) {
  return { category: 'sql', route: 'college.list' };
}
```

**Why It's Broken:**
Query semantic analysis is too shallow:
- "Am I ready" = READINESS query → should route to `ivyscore.latest`
- "Did I get into MIT?" = SPECIFIC COLLEGE query → should route to `college.by_name('MIT')`
- "Show me my reach schools" = FILTERED LIST query → should filter by bucket='Reach'

**Current intent router only detects:**
- Presence of keywords (college, awards, GPA, etc.)
- Does NOT detect:
  - Question type (yes/no, assessment, filtered list, full list)
  - Semantic intent (readiness vs. list retrieval)
  - Filter parameters (specific college, bucket type, date range)

**Impact Scope:**
- "Am I ready" queries → wrong route (college.list instead of ivyscore)
- "Did I get into X?" queries → wrong route (llm instead of college.by_name)
- "Show me reach/target/safety" queries → returns ALL instead of filtering

### Fix 2: **SQL-Level Deduplication**

**Strategy:** Add DISTINCT ON or GROUP BY logic to resolver queries

**Implementation:**

**services/jenny-api/src/resolvers/enums.ts**

**Current Query (awards.final):**
```sql
SELECT family_label AS award, event_time AS date, source_id AS src
FROM kb_items
WHERE student_id = $1
  AND chip_family = 'awards'
  AND source_id IN ('SRC-IMSG-2023-2025', 'SRC-INT-*', ...)
ORDER BY event_time DESC;
```

**Problem:** Returns duplicate rows for same award from different sources

**NEW Query (with deduplication):**
```sql
WITH deduplicated AS (
  SELECT
    -- Normalize award name (remove hyphens, em-dashes, trailing spaces)
    REGEXP_REPLACE(LOWER(family_label), '[—\-\s]+', ' ', 'g') AS award_normalized,
    family_label AS award_original,
    event_time AS date,
    source_id AS src,
    -- Prioritize SRC-INT-* over SRC-IMSG-* (intent sources are canonical)
    CASE
      WHEN source_id LIKE 'SRC-INT-%' THEN 1
      WHEN source_id LIKE 'SRC-COMMONAPP-%' THEN 2
      ELSE 3
    END AS source_priority,
    ROW_NUMBER() OVER (
      PARTITION BY REGEXP_REPLACE(LOWER(family_label), '[—\-\s]+', ' ', 'g'), DATE(event_time)
      ORDER BY CASE
        WHEN source_id LIKE 'SRC-INT-%' THEN 1
        WHEN source_id LIKE 'SRC-COMMONAPP-%' THEN 2
        ELSE 3
      END
    ) AS rn
  FROM kb_items
  WHERE student_id = $1
    AND chip_family = 'awards'
    AND event_time <= NOW()
)
SELECT award_original AS award, date, src
FROM deduplicated
WHERE rn = 1
ORDER BY date DESC;
```

**Change in Code:**

### Fix 3: **Intent Classification Enhancement**

**Strategy:** Add semantic question type detection + filter parameter extraction

**Implementation:**

**services/jenny-api/src/orchestrator/intent-enum.ts**

**NEW: Add question type detection (lines 100-130)**
```typescript
// Semantic question types
const READINESS_PHRASES = ['am i ready', 'ready for', 'can i get into', 'do i have a shot', 'my chances'];
const SPECIFIC_ITEM_PHRASES = ['did i get into', 'did i win', 'do i have', 'what about', 'tell me about'];
const FILTER_PHRASES = {
  reach: ['reach', 'reaches', 'reach schools'],
  target: ['target', 'match', 'targets'],
  safety: ['safety', 'safeties', 'safe schools'],
  accepted: ['accepted', 'got into', 'admitted'],
  rejected: ['rejected', 'didn\'t get in', 'denied'],
  waitlisted: ['waitlisted', 'waitlist'],
};

function detectQuestionType(msg: string): 'readiness' | 'specific' | 'filtered' | 'full_list' {
  const lower = msg.toLowerCase();

  if (READINESS_PHRASES.some(p => lower.includes(p))) return 'readiness';
  if (SPECIFIC_ITEM_PHRASES.some(p => lower.includes(p))) return 'specific';

  // Check for filter keywords
  for (const [filterType, phrases] of Object.entries(FILTER_PHRASES)) {
    if (phrases.some(p => lower.includes(p))) return 'filtered';
  }

  return 'full_list';
}

function extractFilterParams(msg: string): { bucket?: string; decision?: string; name?: string } {
  const lower = msg.toLowerCase();
  const params: any = {};

  // Extract bucket filter (reach/target/safety)
  if (lower.includes('reach')) params.bucket = 'Reach';
  if (lower.includes('target') || lower.includes('match')) params.bucket = 'Match';
  if (lower.includes('safety') || lower.includes('safe')) params.bucket = 'Safety';

  // Extract decision filter
  if (lower.includes('accepted') || lower.includes('got into')) params.decision = 'Accepted';
  if (lower.includes('rejected') || lower.includes('denied')) params.decision = 'Rejected';
  if (lower.includes('waitlist')) params.decision = 'Waitlisted';

  // Extract specific college name (if "did i get into X" pattern)
  const specificMatch = msg.match(/(?:did i get into|what about|accepted to)\s+([A-Z][A-Za-z\s]+)/i);
  if (specificMatch) params.name = specificMatch[1].trim();

  return params;
}
```

```typescript
// services/jenny-api/src/resolvers/college.ts

export async function collegeByName(studentId: string, name: string) {
  const query = `
    SELECT college_name, bucket, decision, attending
    FROM college_list
    WHERE student_id = $1
      AND LOWER(college_name) LIKE LOWER($2)
    LIMIT 1
  `;

  const result = await pool.query(query, [studentId, `%${name}%`]);
  if (result.rows.length === 0) {
    return { college: name, decision: 'Not found in college list' };
  }

  return result.rows[0];
}
```
