## 🎯 Executive Summary

This specification defines a comprehensive **Game Plan / Precision Roadmap** feature that works backwards from college application outcomes to weekly execution. The feature bridges the gap between:
- **Strategic Vision** (Multi-year Ivy+ readiness roadmap)
- **Tactical Execution** (Weekly action plans and progress tracking in Preparation tab)
- **Application Outcomes** (College admission components)
- **Profile Assessment** (Links to Assessment tab for scoring and weak spots)

**Design Philosophy:** First-principles approach working backwards from desired outcome (Ivy+ admission) through multi-year phases down to weekly execution items.

**Key Difference from Assessment Tab:**
- **Assessment Tab:** Shows *where you are* (scoring, strengths, weak spots, target profile)
- **Game Plan Tab:** Shows *how to get there* (multi-year roadmap, phases, tactical plans, opportunities, milestones)

## Part 4: First-Principles UI Specification

### Design Philosophy

**Working Backwards from Outcome:**
```
College Admission (Outcome)
  ↓
Application Components (Common App, Essays, LORs, Test Scores, ECs)
  ↓
Multi-Year Roadmap (Phases with Expected Outcomes)
  ↓
Tactical Plans (Quarterly/Monthly Goals)
  ↓
Weekly Action Plans (Execution Items from v11.0)
  ↓
Daily Tasks (Granular completion units)
```

**Integration with Existing Features:**
- **Weekly Progress Cards (v10.8.2)** - Show actual progress on game plan milestones
- **Weekly Action Plans (v11.0)** - Execution items map to tactical plans
- **Assessment Dashboard** - Readiness score tracks over time

```typescript
interface ProfileAssessment {

interface Strength {

interface WeakSpot {
  weak_spot_id: string;

  title: string;
  description: string;
  priority: 'P0' | 'P1' | 'P2'; // P0 = highest priority/ROI

  target_improvement: string; // What "good" looks like
  tactical_plan: TacticalPlan; // How to address this gap
  deadline: string; // ISO 8601 date
}
```

#### 3. ReadinessScore

```typescript
interface ReadinessScore {
  overall_score: number; // 0-10 scale
  calculated_date: string;
  target_schools_tier: 'Ivy+' | 'Top 20' | 'Top 50' | 'Top 100';

  dimensional_scores: DimensionalScore[];

  historical_scores: HistoricalScore[]; // Track improvement over time
}

interface DimensionalScore {
  dimension: 'academic' | 'extracurricular' | 'awards' | 'service' | 'essays' | 'recommendations' | 'testing';
  score: number; // 0-10
  rationale: string;
  improvement_potential: number; // 0-10 (how much can realistically improve)
  target_score: number; // Goal for this dimension
}

interface HistoricalScore {
  date: string;
  overall_score: number;
  dimensional_scores: { dimension: string; score: number }[];
  notes: string; // What changed since last assessment
}
```

```typescript
interface TargetProfile {

    aptitude: Pillar;

interface Pillar {

  description: string;
```

#### 5. Phase (Multi-Year Roadmap)

```typescript
interface Phase {
  phase_id: string;
  phase_number: number;
  phase_name: string; // e.g., "Exploration & Convergence"

  start_week: number; // Week number in student journey
  end_week: number;
  start_date: string; // ISO 8601
  end_date: string;

  goal: string; // High-level objective for this phase
  expected_outcomes: ExpectedOutcome[];

  key_milestones: Milestone[];

  tactical_plans: TacticalPlan[];

  success_criteria: string[]; // How to measure phase success

  completion_percentage: number; // 0-100

interface ExpectedOutcome {
  outcome_id: string;
  category: 'academic' | 'extracurricular' | 'awards' | 'service' | 'relationships' | 'testing' | 'projects';
  description: string;
  target_date: string;
  achieved: boolean;

  evidence?: string; // Description or link to proof
}

interface Milestone {
  milestone_id: string;
  title: string;
  description: string;
  target_week: number;
  target_date: string;
  status: 'not_started' | 'in_progress' | 'completed' | 'blocked' | 'missed';
  linked_weak_spot_id?: string; // If milestone addresses specific weak spot
  linked_opportunity_id?: string; // If milestone is completing an opportunity
}
```

## Database Schema

### New Tables

#### 1. game_plans

```sql
CREATE TABLE game_plans (
  game_plan_id TEXT PRIMARY KEY,
  student_id TEXT NOT NULL REFERENCES students(student_id),
  created_date TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  created_by TEXT NOT NULL, -- 'Jenny' | 'Agent' | 'System'
  last_updated TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  version INTEGER NOT NULL DEFAULT 1,

  -- JSONB columns for flexible schema
  profile_assessment JSONB NOT NULL, -- ProfileAssessment type
  readiness_score JSONB NOT NULL, -- ReadinessScore type
  target_profile JSONB NOT NULL, -- TargetProfile type
  target_schools JSONB, -- Array of TargetSchool
  school_context JSONB, -- SchoolContext type
  family_context JSONB, -- FamilyContext type (optional)

  current_phase_id TEXT, -- Reference to phases.phase_id

  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_game_plans_student ON game_plans(student_id);
CREATE INDEX idx_game_plans_version ON game_plans(student_id, version DESC);
```

#### 2. game_plan_phases

```sql
CREATE TABLE game_plan_phases (
  phase_id TEXT PRIMARY KEY,
  game_plan_id TEXT NOT NULL REFERENCES game_plans(game_plan_id) ON DELETE CASCADE,
  phase_number INTEGER NOT NULL,
  phase_name TEXT NOT NULL,

  start_week INTEGER NOT NULL,
  end_week INTEGER NOT NULL,
  start_date DATE NOT NULL,
  end_date DATE NOT NULL,

  goal TEXT NOT NULL,
  expected_outcomes JSONB NOT NULL, -- Array of ExpectedOutcome
  success_criteria JSONB, -- Array of strings

  status TEXT NOT NULL CHECK (status IN ('not_started', 'in_progress', 'completed')),
  completion_percentage INTEGER NOT NULL DEFAULT 0 CHECK (completion_percentage >= 0 AND completion_percentage <= 100),

  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_phases_game_plan ON game_plan_phases(game_plan_id);
CREATE INDEX idx_phases_status ON game_plan_phases(game_plan_id, status);
CREATE INDEX idx_phases_week_range ON game_plan_phases(start_week, end_week);
```

#### 3. game_plan_milestones

```sql
CREATE TABLE game_plan_milestones (
  milestone_id TEXT PRIMARY KEY,
  phase_id TEXT NOT NULL REFERENCES game_plan_phases(phase_id) ON DELETE CASCADE,

  title TEXT NOT NULL,
  description TEXT NOT NULL,

  target_week INTEGER NOT NULL,
  target_date DATE NOT NULL,

  status TEXT NOT NULL CHECK (status IN ('not_started', 'in_progress', 'completed', 'blocked', 'missed')),

  linked_weak_spot_id TEXT, -- References weak spot in profile_assessment JSONB
  linked_opportunity_id TEXT, -- References opportunities table

  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_milestones_phase ON game_plan_milestones(phase_id);
CREATE INDEX idx_milestones_status ON game_plan_milestones(status);
CREATE INDEX idx_milestones_target_week ON game_plan_milestones(target_week);
CREATE INDEX idx_milestones_target_date ON game_plan_milestones(target_date);
```

#### 4. tactical_plans

```sql
CREATE TABLE tactical_plans (
  tactical_plan_id TEXT PRIMARY KEY,
  phase_id TEXT NOT NULL REFERENCES game_plan_phases(phase_id) ON DELETE CASCADE,

  title TEXT NOT NULL,
  objective TEXT NOT NULL,

  priority TEXT NOT NULL CHECK (priority IN ('P0', 'P1', 'P2')),

  start_week INTEGER NOT NULL,
  end_week INTEGER NOT NULL,

  steps JSONB NOT NULL, -- Array of TacticalStep
  metrics JSONB, -- Array of Metric

  status TEXT NOT NULL CHECK (status IN ('not_started', 'in_progress', 'completed', 'blocked')),
  completion_percentage INTEGER NOT NULL DEFAULT 0 CHECK (completion_percentage >= 0 AND completion_percentage <= 100),

  linked_weekly_plans JSONB, -- Array of week numbers

  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_tactical_plans_phase ON tactical_plans(phase_id);
CREATE INDEX idx_tactical_plans_priority ON tactical_plans(priority);
CREATE INDEX idx_tactical_plans_status ON tactical_plans(status);
```

#### 5. opportunities

```sql
CREATE TABLE opportunities (
  opportunity_id TEXT PRIMARY KEY,
  game_plan_id TEXT NOT NULL REFERENCES game_plans(game_plan_id) ON DELETE CASCADE,

  title TEXT NOT NULL,
  category TEXT NOT NULL CHECK (category IN ('summer_program', 'competition', 'award', 'internship', 'volunteer', 'research')),

  description TEXT NOT NULL,
  why_recommended TEXT NOT NULL,

  deadline TIMESTAMPTZ NOT NULL,

  application_requirements JSONB, -- Array of strings
  time_commitment TEXT,
  expected_outcomes JSONB, -- Array of strings

  priority TEXT NOT NULL CHECK (priority IN ('P0', 'P1', 'P2')),

  status TEXT NOT NULL CHECK (status IN ('recommended', 'researching', 'applying', 'accepted', 'declined', 'completed')),

  linked_weak_spot_ids JSONB, -- Array of weak_spot_ids
  linked_tactical_plan_id TEXT REFERENCES tactical_plans(tactical_plan_id),

  application_progress JSONB, -- Application progress object

  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_opportunities_game_plan ON opportunities(game_plan_id);
CREATE INDEX idx_opportunities_deadline ON opportunities(deadline);
CREATE INDEX idx_opportunities_priority ON opportunities(priority);
CREATE INDEX idx_opportunities_status ON opportunities(status);
```

#### 6. application_components

```sql
CREATE TABLE application_components (
  component_id TEXT PRIMARY KEY,
  game_plan_id TEXT NOT NULL REFERENCES game_plans(game_plan_id) ON DELETE CASCADE,

  component_type TEXT NOT NULL CHECK (component_type IN ('common_app_essay', 'supplemental_essay', 'activity_list', 'lor', 'test_scores', 'transcript')),

  title TEXT NOT NULL,
  description TEXT,

  linked_game_plan_elements JSONB NOT NULL, -- Object with strength_ids, pillar names, milestone_ids, opportunity_ids

  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),

);

CREATE INDEX idx_application_components_game_plan ON application_components(game_plan_id);
```

## Open Questions

1. **Readiness Score Calculation:** Should this be manually updated by Jenny or auto-calculated based on milestones/progress?
   - **Recommendation:** Manual updates by Jenny initially, with auto-suggestions from system based on milestone completion

2. **Phase Transitions:** How to handle transition from one phase to next?
   - **Recommendation:** Automatic when completion_percentage reaches 100%, with notification to Jenny for review

3. **Weak Spot Archival:** When a weak spot is addressed, should it be archived or remain visible?
   - **Recommendation:** Move to "Addressed Weak Spots" section with strikethrough, keep visible for narrative purposes

4. **Opportunity Rejection:** What if student doesn't want to pursue a recommended opportunity?
   - **Recommendation:** Allow status change to "declined" with optional reason note

5. **Multiple Game Plan Versions:** Should old versions be fully visible or just summaries?
   - **Recommendation:** Summary view for history, full view for latest version only, with "View Previous Version" option
