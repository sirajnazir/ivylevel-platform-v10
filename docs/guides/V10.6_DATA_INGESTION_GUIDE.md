## Data Structure Requirements

### EC Vitals Data Structure

**Required Fields:**
- `vital_id`: Unique ID (format: V001, V002, etc.)
- `student_id`: Student identifier (e.g., 'huda-2025')
- `chip_id`: Links to kb_items.chip_id (e.g., 'E001' for Empowering AI)
- `activity_name`: Name of activity (e.g., 'Empowering AI')
- `metric_type`: One of: `scale`, `financial`, `product`, `leadership`, `impact`, `selection`
- `metric_name`: Specific metric (e.g., 'funding_raised', 'students_reached')
- `as_of`: Snapshot date (YYYY-MM-DD format)
- `source_id`: Provenance (e.g., 'SRC-GAMEPLAN-001', 'SRC-COMMONAPP-001')

**Optional Fields:**
- `numeric_value`: Numeric value (e.g., 23000, 6400)
- `text_value`: Text value for qualitative metrics
- `unit`: Unit of measurement ('$', 'students', 'members', '%')
- `evidence_text`: Original text where metric was extracted
- `notes`: Context notes

**Constraint:** Must provide EITHER `numeric_value` OR `text_value` (or both)

### JTBD Data Structure

**Required Fields:**
- `jtbd_id`: Unique ID (format: J001, J002, etc.)
- `student_id`: Student identifier
- `week_number`: Program week (1-52)
- `week_start_date`: Week start date (YYYY-MM-DD)
- `week_end_date`: Week end date (YYYY-MM-DD)
- `job_type`: One of: `application`, `test`, `award`, `ec_milestone`, `academic`, `essay`, `other`
- `job_description`: Brief description of what was done
- `status`: One of: `planned`, `in_progress`, `completed`, `deferred`, `cancelled`
- `source_id`: Provenance (e.g., 'SRC-SNAPSHOT-2024-06-15')

**Optional Fields:**
- `linked_chip_id`: Links to related entity (kb_items, outcomes, etc.)
- `linked_table`: Table name of linked entity
- `completion_date`: Date completed (required if status = 'completed')
- `outcome_metric`: What metric changed (e.g., 'funding_raised')
- `outcome_value`: Numeric outcome value
- `outcome_unit`: Unit (e.g., '$', 'applications')
- `notes`: Context notes

## Step-by-Step Ingestion Process

### STEP 1: Gather Source Data

**Where to find real data for Huda:**

#### 1.1 GamePlan Data (Initial State)
**Location:** Student intake forms, initial planning documents
**Extracts:**
- Initial EC plans with target metrics
- Baseline numbers (starting team size, initial funding, etc.)

**Example GamePlan extraction:**
```
Activity: Empowering AI
- Initial funding: $5,000 (from local grants)
- Initial reach: 500 students (pilot workshops)
- Team size: 1 (solo founder)
- Date: 2024-01-01
```

#### 1.2 CommonApp Data (Final State)
**Location:** Actual CommonApp submission PDF
**Extracts:**
- Final metrics submitted to colleges
- Activity descriptions with embedded numbers

**Example CommonApp extraction:**
```
Activity: Empowering AI
Description: "An initiative providing resources to girls, fostering education
in AI & ethics. Raised $23k+ in grants for AI education camps/workshops.
6.4k students reached through workshops."

Extracted metrics:
- funding_raised: $23,000 (from "$23k+")
- students_reached: 6,400 (from "6.4k students")
- Date: 2024-10-01 (CommonApp submission date)
```

#### 1.3 Weekly Snapshots (Progression)
**Location:** Weekly coaching session notes, progress trackers
**Extracts:**
- Mid-program metrics
- Milestone achievements
- Week-by-week execution items

**Example weekly snapshot (Week 12):**
```
Week 12: 2024-03-18 to 2024-03-24
- Secured $5k grant for Empowering AI → ec_vitals
- Took SAT (scored 1480) → academic event
- Submitted Kode With Klossy application → jtbd
- Reached 1,000 students milestone → ec_vitals
```

#### 1.4 Session Notes (JTBD Source)
**Location:** Coaching session summaries
**Extracts:**
- What student accomplished that week
- Pending tasks
- Milestones reached

## EC Vitals Ingestion

### Template for EC Vitals Extraction

**Use this template for EACH metric you extract:**

```sql
-- =============================================================================
-- ACTIVITY: [Activity Name]
-- METRIC: [metric_name]
-- SOURCE: [GamePlan | Snapshot | CommonApp]
-- =============================================================================

INSERT INTO ec_vitals (
  vital_id,
  student_id,
  chip_id,
  activity_name,
  metric_type,
  metric_name,
  numeric_value,
  unit,
  as_of,
  source_id,
  evidence_text,
  notes
) VALUES (
  'V[NNN]',                           -- Increment: V001, V002, etc.
  'huda-2025',
  'E001',                             -- chip_id from kb_items
  'Empowering AI',
  'financial',                        -- scale | financial | product | leadership | impact | selection
  'funding_raised',                   -- Specific metric name
  23000,                              -- Numeric value
  '$',                                -- Unit
  '2024-10-01',                       -- Snapshot date
  'SRC-COMMONAPP-001',                -- Source identifier
  'Raised $23k+ in grants for AI education camps/workshops',  -- Original text
  'CommonApp final submission'        -- Context notes
);
```

### Metric Type Guidelines

**scale metrics:**
- `members`, `participants`, `students_reached`, `audience_size`, `geographic_reach`, `membership_growth_rate`

**financial metrics:**
- `funding_raised`, `revenue`, `grants_secured`, `budget_managed`

**product metrics:**
- `products_shipped`, `downloads`, `content_created`, `users_reached`, `views`

**leadership metrics:**
- `team_size`, `partnerships`, `growth_rate`, `role_expansion`

**impact metrics:**
- `people_impacted`, `media_features`, `social_media_reach`, `recognition`

**selection metrics:**
- `acceptance_rate`, `selectivity`, `competition_level`

## Data Validation

### After Ingestion, Validate Data

```sql
-- =============================================================================
-- VALIDATION QUERIES
-- =============================================================================

-- 1. Check total vitals loaded
SELECT COUNT(*) AS total_vitals FROM ec_vitals WHERE student_id = 'huda-2025';
-- Expected: ~20-30 vitals (depending on activity count × metric count × snapshot count)

-- 2. Check vitals by activity
SELECT activity_name, COUNT(*) AS vitals_count
FROM ec_vitals
WHERE student_id = 'huda-2025'
GROUP BY activity_name
ORDER BY vitals_count DESC;

-- 3. Check vitals by metric type
SELECT metric_type, COUNT(*) AS count
FROM ec_vitals
WHERE student_id = 'huda-2025'
GROUP BY metric_type
ORDER BY count DESC;

-- 4. Check progression for funding
SELECT activity_name, metric_name, numeric_value, unit, as_of, source_id
FROM ec_vitals
WHERE student_id = 'huda-2025'
  AND metric_type = 'financial'
  AND metric_name = 'funding_raised'
ORDER BY activity_name, as_of;
-- Expected: Should see progression (e.g., 5000 → 15000 → 23000)

-- 5. Check total JTBD jobs loaded
SELECT COUNT(*) AS total_jobs FROM jtbd WHERE student_id = 'huda-2025';
-- Expected: ~20-30 jobs (depending on weeks tracked × jobs per week)

-- 6. Check jobs by week
SELECT week_number, COUNT(*) AS jobs_count,
       COUNT(*) FILTER (WHERE status = 'completed') AS completed
FROM jtbd
WHERE student_id = 'huda-2025'
GROUP BY week_number
ORDER BY week_number;

-- 7. Check jobs by type
SELECT job_type, COUNT(*) AS count
FROM jtbd
WHERE student_id = 'huda-2025'
GROUP BY job_type
ORDER BY count DESC;

-- 8. Validate temporal views work
SELECT * FROM v_ec_vitals_latest WHERE student_id = 'huda-2025' LIMIT 5;
SELECT * FROM v_ec_vitals_progression WHERE student_id = 'huda-2025' LIMIT 5;
SELECT * FROM v_jtbd_by_week WHERE student_id = 'huda-2025' LIMIT 5;

-- 9. Check for data integrity issues
SELECT COUNT(*) AS missing_numeric FROM ec_vitals
WHERE student_id = 'huda-2025' AND numeric_value IS NULL AND text_value IS NULL;
-- Expected: 0 (must have at least one value)

SELECT COUNT(*) AS missing_completion FROM jtbd
WHERE student_id = 'huda-2025' AND status = 'completed' AND completion_date IS NULL;
-- Expected: 0 (completed jobs must have completion_date)

-- 10. Test vitals summary
SELECT * FROM v_ec_vitals_summary WHERE student_id = 'huda-2025';
-- Expected: Single row with aggregate stats

SELECT * FROM v_jtbd_summary WHERE student_id = 'huda-2025';
-- Expected: Single row with aggregate stats
```

## Troubleshooting

### Common Issues

**Issue 1: Foreign key violation on student_id**
```
ERROR:  insert or update on table "ec_vitals" violates foreign key constraint
DETAIL:  Key (student_id)=(huda-2025) is not present in table "students".
```

**Fix:**
```sql
-- Create student record first
INSERT INTO students (student_id, full_name, grad_year)
VALUES ('huda-2025', 'Huda Ahmed', 2025);
```

**Issue 2: Duplicate vital_id**
```
ERROR:  duplicate key value violates unique constraint "ec_vitals_pkey"
DETAIL:  Key (vital_id)=(V001) already exists.
```

**Fix:**
```sql
-- Check highest vital_id
SELECT MAX(vital_id) FROM ec_vitals WHERE student_id = 'huda-2025';
-- Use next number (e.g., if max is V024, use V025)
```

**Issue 3: Missing chip_id reference**
```
Activity references chip_id = 'E001' but doesn't exist in kb_items
```

**Fix:**
```sql
-- Create kb_items entry first
INSERT INTO kb_items (chip_id, student_id, family, activity_name, source_id, as_of)
VALUES ('E001', 'huda-2025', 'Activity', 'Empowering AI', 'SRC-GAMEPLAN-001', '2024-01-01');
```

**Issue 4: Invalid metric_type**
```
ERROR:  new row for relation "ec_vitals" violates check constraint "ec_vitals_metric_type_check"
```

**Fix:**
```sql
-- metric_type must be one of: scale, financial, product, leadership, impact, selection
-- Check spelling and use lowercase
```

**Issue 5: Completed job without completion_date**
```
ERROR:  new row for relation "jtbd" violates check constraint
```

**Fix:**
```sql
-- If status = 'completed', completion_date is REQUIRED
UPDATE jtbd SET completion_date = week_end_date WHERE status = 'completed' AND completion_date IS NULL;
```

### Method 2: Batch load script

Create `scripts/load_huda_vitals.sh`:

```bash
#!/bin/bash
# Load all Huda vitals and JTBD data

set -e  # Exit on error

echo "Loading Huda's EC Vitals and JTBD data..."

# Check DATABASE_URL
if [ -z "$DATABASE_URL" ]; then
  echo "ERROR: DATABASE_URL not set"
  exit 1
fi

# Load EC Vitals
echo "→ Loading EC Vitals..."
psql $DATABASE_URL -f data/canonical/huda_ec_vitals_gameplan.sql
psql $DATABASE_URL -f data/canonical/huda_ec_vitals_snapshots.sql
psql $DATABASE_URL -f data/canonical/huda_ec_vitals_commonapp.sql

# Load JTBD
echo "→ Loading JTBD..."
for week_file in data/canonical/huda_jtbd_week*.sql; do
  echo "  Loading $week_file..."
  psql $DATABASE_URL -f "$week_file"
done

# Validate
echo "→ Validating data..."
psql $DATABASE_URL -c "SELECT COUNT(*) AS vitals_loaded FROM ec_vitals WHERE student_id = 'huda-2025';"
psql $DATABASE_URL -c "SELECT COUNT(*) AS jobs_loaded FROM jtbd WHERE student_id = 'huda-2025';"

echo "✅ Data loading complete!"
```

### Method 3: Idempotent UPSERT (for re-loading)

If you need to reload data without duplicates:

```sql
-- Use ON CONFLICT for idempotent loads
INSERT INTO ec_vitals (vital_id, student_id, chip_id, activity_name, metric_type, metric_name, numeric_value, unit, as_of, source_id)
VALUES ('V001', 'huda-2025', 'E001', 'Empowering AI', 'financial', 'funding_raised', 5000, '$', '2024-01-01', 'SRC-GAMEPLAN-001')
ON CONFLICT (vital_id) DO UPDATE SET
  numeric_value = EXCLUDED.numeric_value,
  as_of = EXCLUDED.as_of,
  source_id = EXCLUDED.source_id;
```
