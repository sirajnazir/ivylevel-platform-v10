# v3.2 Single Environment Deployment Guide

**Deployment Model:** Production-Safe Single Environment
**Safety Mechanism:** Double-flagged synthetic data (is_synthetic + test_run_id)
**Guarantee:** Always cleans up, never touches real data
**Timeline:** 2-3 hours deployment + validation

---

## 🎯 SINGLE ENVIRONMENT APPROACH

Instead of separate staging/production environments, this guide deploys v3.2 directly to your production database with **bulletproof safety mechanisms**:

1. **Double-flagged synthetic data:** Every test row has `is_synthetic=true` AND unique `test_run_id`
2. **Hard gates:** Script refuses to proceed if safety columns missing or suspicious data found
3. **Scoped deletes:** Cleanup only touches rows with matching `test_run_id` AND `is_synthetic=true`
4. **Residue verification:** Post-delete assertions guarantee zero leftovers
5. **EXIT trap:** Cleanup runs automatically even on failure or Ctrl+C

**Why this is safe:**
- Real student data never has `is_synthetic=true` or `test_run_id` set
- Cleanup uses indexed queries (fast, not table scans)
- Multiple safety gates prevent accidental real-data deletion
- Atomic transactions (all-or-nothing)

### 7.2 Monitor Key Metrics

```bash
# Create monitoring script
cat > scripts/prod_monitor.sh <<'MONITOR'
#!/bin/bash
set -euo pipefail
: "${DATABASE_URL:?Set DATABASE_URL}"

echo "=== v3.2 Production Monitoring ==="
echo "Timestamp: $(date)"
echo ""

# Error rate (last hour)
echo "ERROR RATE (last hour):"
psql "$DATABASE_URL" -c "
SELECT
  COUNT(*) FILTER (WHERE severity = 'ERROR') AS errors,
  COUNT(*) AS total,
  ROUND(100.0 * COUNT(*) FILTER (WHERE severity = 'ERROR') / NULLIF(COUNT(*), 0), 2) AS error_pct
FROM system_events
WHERE created_at > NOW() - INTERVAL '1 hour';
"

# RLS violations (MUST BE ZERO)
echo ""
echo "RLS VIOLATIONS (must be 0):"
psql "$DATABASE_URL" -c "
SELECT COUNT(*)
FROM system_events
WHERE event_type = 'security.rls_violation'
  AND created_at > NOW() - INTERVAL '1 hour';
"

# MV refresh status
echo ""
echo "MV REFRESH STATUS (last hour):"
psql "$DATABASE_URL" -c "
SELECT event_type, COUNT(*)
FROM system_events
WHERE event_type LIKE 'mv.refresh%'
  AND created_at > NOW() - INTERVAL '1 hour'
GROUP BY event_type;
"

# Outbox backlog
echo ""
echo "OUTBOX BACKLOG:"
psql "$DATABASE_URL" -c "
SELECT COUNT(*) AS undelivered
FROM outbox
WHERE delivered_at IS NULL;
"

# PII leaks check (sample chips)
echo ""
echo "PII LEAK CHECK (sample 10 recent chips):"
psql "$DATABASE_URL" -c "
SELECT
  student_id,
  CASE
    WHEN source::text ~* 'email|phone|ssn|@' THEN '❌ POSSIBLE PII LEAK'
    ELSE '✅ Clean'
  END AS pii_check
FROM chips
WHERE is_synthetic = false
ORDER BY created_at DESC
LIMIT 10;
"

echo ""
echo "=== End Dashboard ==="
MONITOR

chmod +x scripts/prod_monitor.sh

# Run every hour
while true; do
  ./scripts/prod_monitor.sh >> /var/log/v3.2_monitoring.log
  sleep 3600
done &
```

## 🆘 TROUBLESHOOTING

### Issue: LAB_MODE error when running canary

**Error:** "LAB_MODE must be set to 'true'"

**Solution:**
```bash
export LAB_MODE=true
./scripts/prod_safe_canary.sh
```

---

### Issue: Canary cleanup shows residue

**Error:** "Residue after cleanup: N rows"

**Cause:** Rows not properly flagged with `is_synthetic=true` or `test_run_id`

**Solution:**
```bash
# Manually inspect residue
psql "$DATABASE_URL" -c "
SELECT table_name, test_run_id, is_synthetic, COUNT(*)
FROM (
  SELECT 'students' AS table_name, test_run_id, is_synthetic FROM students
  UNION ALL
  SELECT 'chips', test_run_id, is_synthetic FROM chips
  -- Add other tables...
) AS all_rows
WHERE test_run_id LIKE 'synth_%'
GROUP BY table_name, test_run_id, is_synthetic;
"

# Manually cleanup if needed (DANGEROUS - verify first!)
# DELETE FROM students WHERE test_run_id = '<specific_run_id>' AND is_synthetic = true;
```

---

### Issue: RLS violations detected in production

**Error:** system_events shows `security.rls_violation` events

**Cause:** CRITICAL - RLS not enforcing properly or code bypassing RLS

**Solution:**
```bash
# IMMEDIATE ACTION: Disable RLS-protected features
export ENABLE_CHIP_CREATOR=false
export ENABLE_HGTI=false

# Investigate violation events
psql "$DATABASE_URL" -c "
SELECT *
FROM system_events
WHERE event_type = 'security.rls_violation'
ORDER BY created_at DESC
LIMIT 10;
"

# Check RLS policies still enabled
psql "$DATABASE_URL" -c "
SELECT schemaname, tablename, policyname, permissive, roles, cmd
FROM pg_policies
WHERE tablename IN ('chips', 'growth_events', 'agent_runs', 'system_events');
"

# If policies missing, re-run migration 007
psql "$DATABASE_URL" -f services/agent-framework/migrations/007_v3.2_production_readiness_facts_views.sql
```

---

### Issue: Workers crash repeatedly

**Cause:** Missing dependencies, Redis connection issues, or database errors

**Solution:**
```bash
# Check logs
tail -100 /var/log/mv-refresher.log
tail -100 /var/log/outbox-processor.log

# Test Redis connection
redis-cli -u "$REDIS_URL" PING
# Expected: PONG

# Reinstall dependencies
cd services/agent-framework
rm -rf node_modules package-lock.json
npm install
npm run build

# Start workers with debug logging
NODE_ENV=development node dist/workers/mv-refresher.js
```
