**IvyLevel Platform - Production-Ready Universal Agent Platform**

**Document Status:** Migration Blueprint
**Created:** 2025-10-16
**Current Version:** v14.0 (Zero-Hallucination Multi-Dimensional Agentic Architecture)
**Target Version:** v1.0 (Universal Agent Platform with 8 Core Agents)

---

## Executive Summary

This document provides a **comprehensive, additive migration strategy** to transform the current v14.0 jenny-api implementation into the v1.0 Universal Agent Platform while:

✅ **Preserving 100% of v14's zero-hallucination architecture**
✅ **Bootstrapping existing infrastructure** (jenny-api, database, env, data)
✅ **Zero breaking changes** to existing functionality
✅ **Incremental implementation** over 20 weeks
✅ **Production-grade** structure aligned with enterprise standards

**Key Principle:** We are **extending, not replacing** v14. Jenny becomes one of 8 agents, and all v14 infrastructure becomes the foundation for the platform.

## Gap Analysis: Current vs Target

### Current State (v14.0)

**Strengths:**
- ✅ Production-ready jenny-api with zero hallucinations
- ✅ 105 temporal views for deterministic facts (CAT-1)
- ✅ Hybrid RAG with Pinecone + PostgreSQL (CAT-2)
- ✅ Fine-tuned EQ adapter (jenny_v9) for empathy (CAT-3)
- ✅ Multi-dimensional intent router with guardrails
- ✅ Complete observability (OTel traces)
- ✅ Jenny Test Lab v4.0 for validation
- ✅ Production database with comprehensive schema
- ✅ Clean architecture with separation of concerns

**Current Architecture:**
```
jenny-api (monolith serving Jenny agent)
├── router/ (intent classification)
├── orchestrator/ (CAT-1/2/3 execution)
├── resolvers/ (SQL queries via 105 views)
├── retrieval/ (hybrid RAG)
├── compose/ (answer generation)
└── quality/ (verification layers)
```

**What's Missing for v1.0:**

### Architecture Gaps

| Component | Current (v14) | Target (v1.0) | Gap Analysis |
|-----------|---------------|---------------|--------------|
| **Agent Framework** | Single monolithic Jenny | 8 modular agents (Game Plan, ECs, Awards, Summer, College, Essay, Weekly, Scholarship) | Need: Agent abstraction layer, BaseAgent class, manifest system |
| **Knowledge Moat** | Basic KB (sessions + iMessage) | Category 2 data (DS1-DS8): CDS, rubrics, hyperlocal, twins, programs, research | Need: 8 new data sources, ingestion pipeline, governance |
| **Orchestration** | Direct orchestrator calls | LangGraph-based multi-agent routing | Need: LangGraph integration, state management, conditional routing |
| **Extensibility** | Hardcoded logic | Visual Builder for custom agents | Need: Manifest system, React Flow UI, validation framework |
| **SDK** | Internal API only | OpenAPI 3.1 + TypeScript/Python SDKs | Need: Spec, code generation, documentation |
| **Data Layer** | Direct PostgreSQL queries | Polymorphic repository pattern | Need: BaseRepository, typed interfaces, caching |
| **Training** | Manual fine-tuning | Continuous learning pipeline | Need: TrainingLogger, A/B testing, automatic fine-tuning |
| **Multi-tenancy** | Single tenant (Huda) | Multi-coach, multi-student | Need: Tenant isolation, RLS policies, scoping |

## Migration Strategy Overview

### Core Principles

1. **Additive Only** - No deletions, only additions and refactoring
2. **Backward Compatible** - Keep `/api/kb-chat` working throughout migration
3. **Incremental** - Ship value every 2 weeks
4. **Feature Flagged** - New features behind flags until stable
5. **Test First** - Golden tests pass before production deployment

### Migration Approach: "Wrap and Extend"

Instead of rewriting, we **wrap v14 components** and **extend with new capabilities**:

```
v14 (Current)                    v1.0 (Target)
─────────────                    ─────────────

jenny-api/                       agent-framework/
├── router/          ──wrap──>   ├── router/ (multi-agent aware)
├── orchestrator/    ──wrap──>   ├── core/UnifiedOrchestrator.ts
├── resolvers/       ──reuse─>   ├── resolvers/ (shared library)
├── retrieval/       ──reuse─>   ├── retrieval/
├── compose/         ──extend─>  ├── composition/
└── quality/         ──reuse─>   └── quality/

                     ──new───>   ├── agents/
                                 │   ├── GamePlanAgent.ts
                                 │   ├── ExtracurricularsAgent.ts
                                 │   ├── AwardsAgent.ts
                                 │   ├── SummerProgramsAgent.ts
                                 │   ├── CollegeListAgent.ts
                                 │   ├── EssayAgent.ts
                                 │   ├── WeeklyExecutionAgent.ts
                                 │   └── ScholarshipAgent.ts

                     ──new───>   ├── core/
                                 │   ├── BaseAgent.ts
                                 │   └── AgentRegistry.ts

                     ──new───>   ├── langgraph/
                                 │   ├── graph.ts
                                 │   └── state.ts

                     ──new───>   ├── repositories/
                                 │   ├── BaseRepository.ts
                                 │   ├── StudentRepository.ts
                                 │   └── MoatRepository.ts

                     ──new───>   └── training/
                                     ├── TrainingLogger.ts
                                     ├── FineTuningPipeline.ts
                                     └── ABTestingFramework.ts
```

### Directory Restructuring

**Phase 1: Rename** (Week 1, Day 1)
```bash
# Rename jenny-api to agent-framework
mv services/jenny-api services/agent-framework

# Update all import paths (automated)
find services/agent-framework -type f -name "*.ts" -exec sed -i '' 's|jenny-api|agent-framework|g' {} +
```

**Phase 2: Add New Directories** (Week 1, Days 2-5)
```bash
cd services/agent-framework

# Create new directory structure
mkdir -p agents
mkdir -p manifests
mkdir -p langgraph
mkdir -p repositories
mkdir -p training
mkdir -p testing

# Create root-level SDK and builder directories
cd ../..
mkdir -p sdk/typescript
mkdir -p sdk/python
mkdir -p apps/agent-builder
```

**Phase 3: Preserve Legacy** (Throughout)
```bash
# Keep old imports working via barrel exports
# services/agent-framework/src/index.ts
export * from './router';
export * from './orchestrator';
export * from './resolvers';
// ... etc
```

## Risk Mitigation

### Critical Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| **Breaking v14 functionality** | High | Feature flags, parallel deployment, extensive regression testing |
| **Data quality in Category 2 sources** | High | Validation layer, trust scoring, manual review of critical sources |
| **LangGraph complexity causes bugs** | High | Start with simple linear graph, gradual rollout |
| **Performance degradation** | High | Load testing each phase, caching, connection pooling |
| **Agent routing errors** | Medium | User override, detailed logging, confidence thresholds |

### Mitigation Strategies

1. **Feature Flags**
   - All new features behind flags in `.env`
   - Can rollback instantly

2. **Parallel Deployment**
   - Keep `/api/kb-chat` (v14) alongside `/agent/chat` (v1.0)
   - Route 1% traffic to v1.0 initially

3. **Golden Test Gate**
   - Must pass 100% before production
   - Automated in CI/CD

4. **Rollback Plan**
   - Git tags for each phase
   - Database migration rollback scripts
   - Blue-green deployment
