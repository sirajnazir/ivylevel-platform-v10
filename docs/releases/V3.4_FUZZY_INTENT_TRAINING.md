# V3.4: Fuzzy Intent Training Pack — Comprehensive Synonym Expansion

**Date**: 2025-10-03
**Status**: ✅ Implemented
**Version**: v3.4 (GPT-5 Intent Router Enhancement)

---

## Summary

Enhanced the GPT-5 intent router with a comprehensive 48-example training pack, fuzzing recipe with synonym expansion, and tiered confidence-based routing to eliminate brittleness and handle natural language variations robustly.

**Key Improvements:**
- ✅ 48 comprehensive few-shot examples (up from ~30)
- ✅ Fuzzing recipe with phase/object synonym bags
- ✅ Standardized intent schema (intent + phase + object + filters)
- ✅ Tiered confidence routing (route ≥0.62, clarify 0.45-0.62, suggest <0.45)
- ✅ Keyword floor detection for generic "academics" queries
- ✅ Support for progression.timeline and sat.ordinal intents

---

## Problem Statement

**Previous Issues (v3.3):**
1. **Phrasing brittleness**: Queries like "what ECs did I add to my college app?" would fall through to RAG instead of routing to final ECs list
2. **Synonym gaps**: Natural variations ("game plan" vs "gameplan", "submitted" vs "as submitted") weren't covered
3. **Intent ambiguity**: No clear handling for progression queries ("which awards did I win?") vs list queries ("final awards list")
4. **Confidence blind spots**: All queries either routed or got generic clarification—no middle ground for "I think you mean X" suggestions

## Solution Architecture

### 1. Standardized Intent Schema

**Old Schema (v3.3):**
```typescript
{
  intent: "ecs.list" | "awards.wins" | "academics.sat" | ...
  entity: "ecs" | "awards" | "programs" | "academics" | "narrative"
  phase: "initial" | "final" | "progression" | "latest" | "first" | "nth" | "none"
  slots: { date?: string, nth?: number, metrics?: string[] }
  confidence: number
}
```

**New Schema (v3.4):**
```typescript
{
  intent: "ecs.list" | "awards.list" | "programs.list" |
          "academics.summary" | "narrative.summary" |
          "progression.timeline" | "sat.ordinal" | "kb.search" | "unknown"
  phase: "initial" | "final" | null
  object: "ec" | "award" | "program" | "academics" | "narrative" | "sat"
  filters: {
    as_of?: string | null
    school?: string | null
    scope?: string | null          // national/regional/international
    nth?: string | number | null   // "first" | "second" | "latest" | 1 | 2
    components?: string[] | null    // ["grades", "gpa", "sat", "ap", "transcript"]
  }
  confidence: number
  detector?: "llm" | "keyword-floor"
}
```

**Key Changes:**
- `phase` simplified to `"initial" | "final" | null` (removed "progression", "latest", "first", "nth", "none")
- Added `object` field to clearly identify what entity the query is about
- Consolidated `slots` into structured `filters` object
- Added `detector` field to track whether keyword floor or LLM classified the intent
- Removed entity-specific intents (awards.wins, programs.admits) in favor of `progression.timeline` + object filter
- Added `sat.ordinal` for first/second/latest SAT queries

### 3. Fuzzing Recipe (Synonym Bags + Auto-Expansion)

**Implementation:**
```typescript
const PHASE_SYNONYMS = {
  initial: ["initial", "at the start", "in the game plan", "planned", "kickoff", "early", "baseline", "gameplan", "game plan"],
  final: ["final", "as submitted", "in the Common App", "in my college application", "submitted", "what made it", "what ended up", "application"]
};

const OBJECT_SYNONYMS = {
  ec: ["ECs", "activities", "extracurriculars", "clubs", "involvements"],
  award: ["awards", "honors", "prizes", "distinctions"],
  program: ["summer programs", "summer camps", "summer plan programs", "selective programs"],
  academics: ["academics", "grades and tests", "transcript and scores", "GPA and SAT", "academic stats"],
  narrative: ["narrative", "USP", "story", "identity", "passion", "aptitude", "cause", "why-statement"]
};

const ACCEPTANCE_VERBS = ["got in", "get in", "got into", "accepted to", "admitted to", "made it into"];
const ORDINALS = ["first", "second", "third", "latest", "last", "earliest", "initial"];
```

**Fuzzing Strategy:**
1. **Phase Detection**: Match any synonym from `PHASE_SYNONYMS.initial` or `PHASE_SYNONYMS.final`
2. **Object Detection**: Match any synonym from `OBJECT_SYNONYMS.*`
3. **Acceptance Verbs**: If query contains acceptance verb + object → route to `progression.timeline`
4. **Ordinals**: If query contains ordinal + "SAT" → route to `sat.ordinal`

**Auto-Expansion Recipe** (for future enhancement):
- Compose `PHASE? + OBJECT + ACTION?` with 10% noise injections (typos/article removals)
- Generate 500+ variants at boot time
- Add 5-10% ambiguous prompts for abstention training ("what about my activities?")

### 4. Tiered Confidence Routing

**Confidence Thresholds:**
```typescript
const ROUTE_THRESHOLD = 0.62;      // Route to resolver if confidence >= 0.62
const CLARIFY_THRESHOLD = 0.45;    // Ask clarifying question if 0.45-0.62
```

**Routing Logic:**

**Tier 1: Very Low Confidence (< 0.45)**
```
I'm not quite sure what you're asking for. Try asking for something specific like:
• "final EC list"
• "initial awards list"
• "what awards did I win?"
• "what was my first SAT score?"
```
- **Logged as**: `intent.very_low_confidence`
- **Action**: Suggest specific query examples
- **UX**: Red chip with confidence percentage

**Tier 2: Medium Confidence (0.45-0.62)**
```
I think you want **final ECs**—should I pull that? (58% confident)

Or try rephrasing your question for better accuracy.
```
- **Logged as**: `intent.mid_confidence`
- **Action**: Show best guess + ask for confirmation
- **UX**: Yellow chips with inferred intent and confidence
- **Example**: Query "what activities did I do?" → 55% confident it's "final ECs"

**Tier 3: High Confidence (≥ 0.62)**
- **Action**: Route directly to SQL resolver
- **UX**: Execute query and return results
- **Example**: "what was my final EC list?" → 95% confident → route to `ecsList(pg, studentId, "final")`

### 5. Updated System Prompt

**Key Rules:**

**Phase Mapping:**
```
- "initial", "gameplan", "game plan", "planned", "at the start", "kickoff", "early", "baseline" → phase:"initial"
- "final", "submitted", "application", "college app", "CommonApp", "as submitted", "made it", "ended up" → phase:"final"
- For progression/timeline queries → phase:null
- For ordinal queries (first/second/latest SAT) → phase:null
```

**Intent Routing Rules:**
```
- "which ECs/awards/programs did I win/get in/get into?" → intent:"progression.timeline", phase:null
- "what was my first/second/latest SAT?" → intent:"sat.ordinal", phase:null, filters:{nth:"first"|"second"|"latest"}
- "SAT progression" → intent:"progression.timeline", phase:null, object:"sat"
- "show progress from plan to outcome" → intent:"progression.timeline", phase:null
- "initial [object] list" → intent:"[object].list", phase:"initial"
- "final [object] list" → intent:"[object].list", phase:"final"
```

**Academics Handling:**
```
- Extract components from query: "grades", "gpa", "sat", "act", "ap", "transcript"
- "what was my initial academics?" → intent:"academics.summary", phase:"initial", filters:{components:["grades","sat","gpa"]}
- "final GPA and SAT" → intent:"academics.summary", phase:"final", filters:{components:["gpa","sat"]}
- Always populate filters.components for academics queries
```

**Confidence Guardrails:**
```
- High confidence (>=0.85): Clear phase + object match
- Medium (0.6-0.84): Fuzzy phrasing but clear intent
- Low (<0.6): Ambiguous or missing critical slots
- NEVER hallucinate; return low confidence if unclear
```
