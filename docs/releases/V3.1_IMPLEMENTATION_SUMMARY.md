## Key Technical Decisions

1. **Vitals-First Architecture**: All factual queries check vitals before RAG
2. **Kind-Locked Queries**: Prevents mixed document types in search results  
3. **Dynamic Namespace Routing**: Maps document kinds to Pinecone namespaces
4. **Evidence Chips Required**: Every response must cite its data source
5. **Never-Blank Doctrine**: Always offer next action instead of saying "no access"

## Data Flow for SAT Query

1. User asks "What is my SAT score?"
2. Orchestrator detects factual query → structured-first lane
3. Reads vitals directly via `readVitals()` → finds current: 1530
4. Checks canon registry for authoritative source
5. Returns "Your current SAT score is 1530" with evidence chip
6. Never returns historical score (1480) from first attempt
